# Imported-map rendering: contributor notes

These notes describe the current implementation and its limitations, not a promise that arbitrary Unity maps will render correctly. Rendering repairs are selected per course through `mapLighting` in the course JSON. Start with the values for a known map and test any change in that map and at least one other imported map.

## Loading and ownership

`MapSceneRuntime` loads the declared dependency bundles and scene bundle, then loads the scene additively alongside a game course. `CourseScenePatcher` hides the base scenery, adjusts imported rendering and places game objects. While the imported map is active, it disables enabled lights from the hidden base course, except for a base sun explicitly selected by `preferBaseCourseSun`; the previous light states are restored during cleanup. Its other snapshot collections restore the base scene and changed terrain/LOD settings; temporary textures, materials, meshes and objects have their own cleanup lists. Changes to this lifecycle must account for an interrupted load and repeated rounds. Imported material shaders are currently modified in place, so do not assume these material mutations are independently snapshotted.

`RepairImportedMapRendering` scans scene renderers and, where enabled, terrain tree/detail prototypes. Many BONELAB shader graphs depend on code, texture layouts or shader variants that are absent in Disc Golf Masters. `forceUnlitMaterials` selects a source color texture and applies an available URP unlit shader; that is a compatibility fallback, not a full shader conversion. Lighting, wind, normal maps, atlases, transparency and shader-specific parameters may therefore differ from the source map. Avoid applying map-specific fixes globally.

## Tree Land

Tree Land enables terrain shader repair, rebuilt terrain texture details, the base game's skybox, hiding its holographic wall, and mesh LODs for terrain trees. The original billboard shader uses a layout the fallback does not reproduce, so mesh LODs are preferred. This increases the amount of geometry drawn and billboard-only vegetation can disappear. Its captured leaf atlas has a nontrivial alpha channel; the URP unlit fallback did not render its cutouts correctly. The URP lit cutout fallback (`useLitFoliageMaterials`) improved foliage in the 0.5.10 game test, although lighting and shadows still needed work.

The experimental `realtimeMapShadows` option also uses the URP lit fallback for opaque map surfaces, enables casting/receiving on imported mesh renderers, enables terrain casting and selects an imported directional sun. Its previous light, terrain and renderer settings are restored on cleanup. Hood Corner and Tree Land enable it locally. A 0.5.16 Tree Land gameplay check found the imported scene extremely dark, without visible trunk, rock, or shrub shadows. The user also reports that branches do not move with wind or impact, and do not affect or slow the disc. The 0.5.16 log records Tree Land loading, tree-material instancing, 342 scene-level collision proxies, and a successful raycast against the first proxy; these diagnostics did not predict the gameplay results. Chains reportedly became visible only after being hit. Keep shadow and canopy collision options experimental until lighting, shadows, throw interactions, chain initialization, and performance are verified in game. Diagnostics only observe the pipeline; they do not adjust game quality settings. Maps without `realtimeMapShadows` retain the prior fallback. Imported particle shaders are preserved; `hideImportedParticles` can hide imported particle renderers entirely.

For targeted diagnosis, `exportFoliageDiagnostics` can be enabled in a course's `mapLighting`. On scene load, the loader saves PNG captures of selected foliage textures under `BepInEx/plugins/CustomCourseLoader/Diagnostics/Foliage/` and logs their paths in `BepInEx/LogOutput.log`. This reads back textures through Unity's render pipeline, so a capture is diagnostic evidence, not a byte-for-byte export of the source asset. Disable the flag when finished. These captures may contain third-party map assets and should stay local unless their owner permits sharing.

When examining a failed material, check the logged original shader, texture candidates, selected color texture, alpha channel and any shader-specific masking or atlas transforms. A shader can report that it is supported while still render incorrectly; an enabled keyword also does not prove that the needed compiled shader variant exists in the game. Test any repair with both leaf and non-leaf cutout materials so that fences and vegetation are not regressed.

When preserving source lightmaps, the render scan reports the number of active lightmap data entries and renderer paths whose baked or realtime lightmap indices fall outside that array. This flags invalid indices that can leave imported surfaces unlit or unstable; valid index ranges do not prove that the textures correspond to the intended scene.

For a course that enables `ignoreSourceTint`, each unresolved material now logs its first renderer hierarchy path and world bounds alongside the shader and texture result. Use this to identify whether a dark or blank area is a textureless mesh, then inspect the corresponding source material before adding a course-specific texture mapping. The message is diagnostic only; tint-only and vertex-color geometry may legitimately have no texture.

The local 0.5.33 Milsim Forest captures for `natureplants00491`, `sprucebranch`, `detailsprites9`, `Urban_Trees_branches02_small`, `bush`, and `cvetochke` are RGBA textures with both transparent and opaque alpha samples. This confirms that these selected texture images contain alpha; it does not prove that the replacement shader's alpha-test variant or the source atlas UV transform is correct. If solid cards or garbled foliage persist, inspect the material/shader state and terrain-detail prototypes before adding more material-name heuristics. Keep the captures in player diagnostics; they are excluded from source archives.

## 0.5.18 experiment status

Version 0.5.18 added experimental DGM foliage-shader and foliage-trigger options, base-course sun selection, ambient fill, and a moved-basket chain wake-up. Its imported-map setup crashed when a diagnostic call entered `Dgm.FoliageSweep.Classify`; `BepInEx/ErrorLog.log` records an `AccessViolationException` from that call. Version 0.5.19 removes the direct diagnostic call, and the Tree Land example disables canopy triggers, the DGM foliage shader, and base-sun selection. The installed 0.5.16 rollback loaded Tree Land and all nine holes, but that does not verify 0.5.19 or the 0.5.18 feature changes. The canopy-trigger option remains available in the editor and its disc-impact behavior is unverified. Keep these features experimental until a 0.5.19 game run confirms map loading, lighting, shadows, foliage behavior, chain visibility, and performance.

## Regression checks

- Build against the installed game's BepInEx IL2CPP interop assemblies and confirm the installed DLL hash matches the build. A successful compile does not verify Unity methods are available at runtime: an interop stub can fail with `Method unstripping failed` or cause a native crash.
- Load Tree Land, inspect nearby and distant trees, grass, ground, sky and walls; throw a disc and check the landing, basket and out-of-bounds behavior. Review `BepInEx/LogOutput.log` and `BepInEx/ErrorLog.log` for warnings, exceptions and crashes.
- Load Hood Corner and a base-game course after returning to the menu. Check that imported-map lighting, visibility and bounds do not leak into the next round. Check course selection and scrolling as well.
- Changes to native-facing `Il2CppSystem.Collections.Generic.List<SoloConfiguration.SoloCourse>` operations have previously caused access violations. Preserve the current UI injection approach unless an alternative is verified in the actual game.
